# Лабораторная работа 2. Потоки. Процессы. Асинхронность

## Цель работы

Цель лабораторной работы — изучить различия между потоками, процессами и асинхронным программированием в Python, а также сравнить их эффективность на вычислительных и сетевых задачах.

## Задача 1. Сумма чисел от 1 до 10 000 000 000 000

В первой задаче требовалось написать три программы, которые считают сумму всех чисел от 1 до 10 000 000 000 000 с использованием разных подходов:

- `threading`;
- `multiprocessing`;
- `asyncio`.

Задача была разделена на несколько диапазонов. Каждый диапазон обрабатывался отдельной задачей. Для вычисления суммы внутри диапазона использовалась формула арифметической прогрессии:

```text
sum = (start + end) * count / 2
```

Прямой перебор чисел циклом до 10 000 000 000 000 практически невозможен по времени, поэтому использование формулы является более корректным решением.

### threading

В программе `task1_threading.py` создается несколько потоков. Каждый поток считает сумму на своем участке диапазона. После завершения всех потоков результаты складываются.

Особенность подхода: в CPython существует GIL, из-за которого несколько потоков не могут одновременно выполнять Python-байткод на разных ядрах процессора. Поэтому для CPU-bound задач потоки обычно не дают значительного ускорения.

### multiprocessing

В программе `task1_multiprocessing.py` используется пул процессов. Каждый процесс получает свой участок диапазона и считает частичную сумму. Затем главный процесс собирает результаты.

Особенность подхода: каждый процесс имеет собственный интерпретатор Python и собственный GIL. Поэтому `multiprocessing` подходит для вычислительно тяжелых задач.

### asyncio

В программе `task1_async.py` создаются асинхронные задачи. Они запускаются через `asyncio.gather`.

Особенность подхода: `asyncio` не ускоряет CPU-bound вычисления само по себе, потому что работает в одном потоке. Его главная область применения — задачи ввода-вывода, например сетевые запросы.

## Задача 2. Параллельный парсинг веб-страниц

Во второй задаче требовалось написать три программы для параллельного парсинга нескольких веб-страниц и сохранения результатов в базу данных.

Для хранения данных используется PostgreSQL-база из лабораторной работы 1. Данные сохраняются в таблицу `trips`.

Структура используемой таблицы:

| Поле | Тип | Описание |
|---|---|---|
| id | integer | Первичный ключ |
| title | character varying | Заголовок страницы |
| description | character varying | Описание с URL страницы и используемым подходом |
| owner_id | integer | Внешний ключ на пользователя, для данных парсинга заполняется значением NULL |

Для сохранения используется запрос:

```sql
INSERT INTO trips (title, description, owner_id)
VALUES (..., ..., NULL)
```

### threading

В программе `task2_threading.py` для каждого URL создается отдельный поток. Каждый поток загружает страницу через `requests`, получает HTML, парсит тег `<title>` через `BeautifulSoup` и сохраняет результат в базу.

Этот подход хорошо подходит для сетевых задач, потому что во время ожидания ответа от сервера другие потоки могут продолжать работу.

### multiprocessing

В программе `task2_multiprocessing.py` используется пул процессов. Каждый процесс обрабатывает отдельный URL.

Этот подход работает, но для сетевого парсинга он обычно менее удобен, потому что создание процессов тяжелее, чем создание потоков или async-задач.

### asyncio

В программе `task2_async.py` используется `aiohttp` для асинхронных HTTP-запросов и `aiosqlite` для асинхронной записи в базу данных.

Этот подход хорошо подходит для большого количества сетевых запросов, потому что одна программа может эффективно переключаться между задачами во время ожидания ответа от сервера.

## Сравнение подходов

Для первой задачи наиболее подходящим является `multiprocessing`, потому что задача относится к вычислительным. Потоки в Python ограничены GIL, а `asyncio` не предназначен для ускорения вычислений.

Для второй задачи лучше подходят `threading` и `asyncio`, потому что парсинг веб-страниц является I/O-bound задачей. Программа большую часть времени ждет ответа от внешнего сервера, поэтому во время ожидания можно выполнять другие задачи.

`asyncio` обычно является наиболее легковесным решением для большого количества сетевых запросов. `threading` проще для понимания и тоже хорошо работает на небольшом количестве URL. `multiprocessing` для парсинга использовать можно, но чаще это избыточно.

## Вывод

В ходе лабораторной работы были реализованы три подхода к параллельному выполнению задач в Python: потоки, процессы и асинхронность. Было показано, что выбор подхода зависит от типа задачи.

Для вычислений лучше подходит `multiprocessing`, потому что он позволяет использовать несколько ядер процессора. Для сетевых запросов лучше подходят `threading` и `asyncio`, так как они эффективно работают с ожиданием ввода-вывода.
